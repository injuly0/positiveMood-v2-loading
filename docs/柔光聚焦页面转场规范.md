# 柔光聚焦页面转场规范

> 用途：作为本项目后续页面转场的统一实现依据。当前首要落地场景是 `RecordEntryPage`（记录页）→ `QuestionSelectionPage`（问题选择页）。
>
> 基准：现有“初始页 → 记录页”实现，见 `src/App.tsx` 与 `src/App.css`。

## 1. 体验目标

项目中的页面切换不应像硬切路由，而应像用户把注意力落在一个行动点上：该点亮起柔和暖光，光晕扩散并包住当前空间；在画面被完全覆盖时完成页面切换；随后光感淡去，新页面自然显现。

统一体验关键词：

- **聚焦**：光从用户刚刚点击的控件中心产生，而不是固定从屏幕中心出现。
- **柔和**：边缘必须渐隐、带模糊，不出现硬圆、纯白闪屏或锐利遮罩。
- **暖色**：使用暖白和低饱和粉棕色，延续初始页的信件与室内光感。
- **连续**：旧页和新页被同一个常驻覆盖层连接，路由切换不能中断动画。
- **克制**：动画只强调空间转移，不与页面内容抢夺注意力。

## 2. 标准运动叙事

一次完整转场只有三个状态：

| 状态 | 含义 | 页面行为 | 覆盖层行为 |
| --- | --- | --- | --- |
| `idle` | 无转场 | 页面可交互 | 光斑不可见 |
| `covering` | 柔光覆盖旧页 | 禁止再次触发转场 | 光从触发点扩大，旧页轻微推近 |
| `revealing` | 揭示新页 | 新路由已经挂载 | 满屏柔光保持原尺寸并淡出 |

标准时间线：

| 时间点 | 动作 |
| --- | --- |
| `0ms` | 读取点击控件的中心坐标，锁定本次转场，进入 `covering` |
| `0–220ms` | 旧页标题、提示或高对比辅助元素快速淡出 |
| `0–540ms` | 暖白光斑从 `scale(.2)` 扩散至覆盖视口；旧页可轻微放大至 `1.018` |
| `500ms` | 光已基本遮住旧页，在视觉不可见处执行 `navigate(target)` |
| `540ms` | 进入 `revealing`，开始揭示新页 |
| `540–970ms` | 光斑不再缩放，仅从不透明淡出，避免产生“吸回原按钮”的倒放感 |
| `1000ms` | 回到 `idle`，解锁下一次转场 |

关键原则：**路由只能在覆盖峰值附近切换，不能在点击瞬间切换。**

## 3. 视觉参数

以下参数来自当前已实现的初始页转场，后续页面默认复用，不要自行改成另一套光感。

### 3.1 光斑基础

```css
--transition-background: #fffaf7;
--transition-accent: #d8b7a6;
--light-size: 28px;
```

光斑为圆形径向渐变：

```css
background: radial-gradient(
  circle,
  color-mix(in srgb, var(--transition-background) 86%, var(--transition-accent)) 0 34%,
  color-mix(in srgb, var(--transition-background) 74%, var(--transition-accent)) 58%,
  color-mix(in srgb, var(--transition-background) 58%, transparent) 78%,
  transparent 100%
);
```

覆盖阶段：

- 尺寸：`28px × 28px`
- 起始：`opacity: 0; scale(.2); blur(8px)`
- 18% 处：`opacity: .72`
- 结束：`opacity: 1; scale(var(--light-scale)); blur(2px)`
- 时长：`540ms`
- 缓动：`cubic-bezier(.55, .04, .7, .98)`

揭示阶段：

- 保持最大 `scale`，只改变透明度
- `opacity: 1 → 0`
- 时长：`430ms`
- 缓动：`ease-out`

### 3.2 覆盖层

覆盖层必须：

```css
position: fixed;
inset: 0;
z-index: 9999;
overflow: hidden;
pointer-events: none;
```

覆盖层必须位于路由页面之外并在路由切换时保持挂载。不能把它只写在记录页内部，否则 `navigate` 后组件卸载，揭示阶段会被截断。

### 3.3 旧页配合动作

旧页在 `covering` 时可以有一个极轻的景深推进：

```css
transform: scale(1.018);
transition: transform 520ms cubic-bezier(.32, .72, 0, 1);
```

这属于辅助动作，不是每个页面都强制使用。页面若包含输入框等容易因缩放变糊的元素，可只让页面背景或内容容器轻微放大；如果没有合适容器，可以完全省略缩放，但不能省略柔光覆盖层。

## 4. 光源位置与覆盖范围

### 4.1 光源位置

使用本次点击控件的实际中心：

```ts
const rect = trigger.getBoundingClientRect();
const x = rect.left + rect.width / 2;
const y = rect.top + rect.height / 2;
```

对于“记录页 → 问题选择页”，光源是“提交记录并继续”按钮的中心。不要使用页面中心，也不要使用鼠标指针坐标；按钮中心在键盘触发和触屏场景下仍然稳定。

### 4.2 最大缩放计算

光斑必须到达离光源最远的视口角，并保留柔光透明边缘所需的安全余量：

```ts
const viewportWidth = document.documentElement.clientWidth;
const viewportHeight = document.documentElement.clientHeight;
const farX = Math.max(x, viewportWidth - x);
const farY = Math.max(y, viewportHeight - y);
const radius = Math.hypot(farX, farY);
const scale = Math.ceil((radius * 2.35) / 28);
```

`2.35` 是覆盖安全系数，包含渐变外圈透明区。不要只按圆的几何直径计算，否则屏幕最远角可能在路由切换时短暂露出旧页。

## 5. 推荐组件边界

应把现有只服务 `/record` 的 `startRecordTransition` 泛化为路由级能力，例如：

```ts
type TransitionState = 'idle' | 'covering' | 'revealing';

interface SoftFocusTransitionOptions {
  trigger: HTMLElement;
  to: string;
  beforeNavigate?: () => void;
}

type StartSoftFocusTransition = (
  options: SoftFocusTransitionOptions,
) => void;
```

职责划分：

- 路由级控制器：保存 `transitionState`、光源几何信息、运行锁与定时器；在覆盖峰值执行 `navigate`。
- `WarmLightTransitionLayer`：只负责根据状态和几何信息渲染动画，不读取业务 Store。
- 页面：完成校验和业务数据写入，然后把触发按钮与目标路由交给控制器。
- Zustand Store：只保存可恢复的业务草稿；不要保存动画阶段、定时器或光源坐标。

覆盖层可以继续放在 `AppRoutes` 的 `<Routes>` 外侧，也可以放入不会随子路由卸载的顶层 Layout；无论采用哪种结构，都必须覆盖 `/` 与所有业务路由。


## 6. 并发、卸载与异常处理

- 使用运行锁（如 `runningRef`）忽略动画期间的重复点击。
- 进入 `covering` 后，触发按钮应在语义上不可再次提交；运行锁是最后保护。
- 所有 `setTimeout` ID 放在统一数组中，顶层控制器卸载时全部清除。
- 转场过程中不要再次读取触发元素位置；第一次点击时记录的坐标就是本次光源。
- 导航目标应由本次调用捕获，不能用一个可能被后续点击覆盖的普通变量。
- 业务校验失败、用户取消确认或写入草稿失败时，不得启动动画。
- 直接访问 URL、浏览器前进后退和守卫重定向默认不播放本转场；它们没有明确的用户点击焦点。

## 7. 可访问性与减少动态效果

必须尊重：

```ts
window.matchMedia('(prefers-reduced-motion: reduce)').matches
```

减少动态效果时使用现有短时间线：

| 动作 | 时间 |
| --- | --- |
| 切换路由 | `120ms` |
| 开始揭示 | `130ms` |
| 完成并解锁 | `250ms` |

此模式下光斑从一开始就使用最大尺寸，只做 `120ms` 的柔和淡入与淡出，不执行空间扩张，也不做旧页缩放。

补充要求：

- 覆盖层使用 `aria-hidden="true"`，不进入辅助技术阅读顺序。
- 动画期间不要把焦点移到覆盖层。
- 新页挂载后按页面既有规则管理焦点；不要强行聚焦仅用于装饰的元素。
- 光效不能成为唯一的状态反馈，提交按钮文案与加载页仍要表达当前进度。

## 8. 禁止的实现方式

- 点击后立即 `navigate`，再在新页单独播放一段入场动画。
- 把覆盖层写在会随旧页卸载的页面组件内。
- 用固定屏幕中心代替点击控件中心。
- 揭示阶段把光斑缩回按钮，造成视觉倒退。
- 使用不透明纯白块直接闪屏，或将 `filter: blur()` 去掉形成硬边。
- 为每一对页面复制一份独立定时器和 CSS。
- 把动画状态写入 Zustand Persist，导致刷新后恢复到半截动画。
- 为等待接口而无限延长满屏覆盖时间。
- 动画运行期间允许重复提交或启动第二次路由切换。

## 10. 验收标准

### 10.1 视觉验收

- 光从实际点击按钮中心产生。
- 光晕边缘柔和，无清晰圆边、色带和纯白闪烁。
- 路由切换瞬间视口四角均被覆盖，看不到旧页跳成新页。
- 新页通过原尺寸光层淡出显现，没有“光缩回旧按钮”的错觉。
- 桌面、窄屏和按钮靠近视口边缘时均能完整覆盖。
- 整体节奏与现有“初始页 → 记录页”主观一致。

### 10.2 交互验收

- 空输入和取消覆盖旧草稿时不跳页、不播放转场。
- 有效提交只创建一次草稿、只导航一次。
- 连续快速点击不会叠加动画或重复提交。
- 问题生成未完成时，转场结束后正常看到 `ThinkingLoader`。
- 问题已经存在时，转场结束后直接看到问题选择内容。
- 浏览器前进、后退以及直接访问路由不残留覆盖层。

### 10.3 无障碍验收

- `prefers-reduced-motion: reduce` 下不出现扩张运动，约 `250ms` 内结束。
- 键盘触发提交时，光源仍为按钮中心。
- 覆盖层不阻挡点击、不被读屏读取。

## 12. 后续页面如何复用

后续任何明确由用户点击动作发起的“进入下一空间”都可复用同一机制，只需提供：

1. 点击控件 `trigger`；
2. 目标路由 `to`；
3. 必要时在导航前完成的同步业务写入。

默认保持相同颜色、扩张曲线和总时长，以形成项目级的连续语言。只有在转场表达完全不同的产品语义时才使用其他动画，例如“回答结晶为记忆”继续采用独立的 `CrystallizeOverlay`；不要把结晶动画和柔光聚焦动画混为一套。
