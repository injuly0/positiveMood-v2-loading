## 1. 页面目标

记录页用于让用户围绕当天的引导问题书写一段记忆。

页面需要清晰呈现：

- 日期；
- 当天主题标签；
- 动态引导问题；
- “换一个”按钮；
- 信件正文输入区域；
- 自动保存状态；
- 字数统计；
- “收藏这份记忆 →”操作入口。

页面还需支持：

- 用户停止输入 1 秒后触发自动保存；
- 保存状态按 `default → saving → saved / error` 变化；
- 点击“换一个”时同步更换主题标签和引导问题；
- 新问题必须来自与新主题标签匹配的问题框架。

视觉重心是画面中央的信纸。背景负责营造沉浸感，不承载文字和交互。

## 4. 组件化判断

### 4.1 应拆为组件

#### `RecordPage`

页面级容器，组合背景、信纸和项目已有的数据逻辑。

#### `RecordPageBackground`

只负责记录页背景资源和舞台铺放。

#### `LetterArtworkImage`

信纸主体本身是完整图片资产，不是固定宽高的 DOM 面板。

要求：

- 图片资源尺寸与背景图一致，均为 `1440 × 810`；
- 绝对定位于舞台原点 `(0, 0)`；
- 与背景图使用完全相同的等比缩放；
- 不单独规定或计算可见信纸区域的宽高；
- 不横向拉伸，也不根据正文内容改变尺寸。
- v6 替换为 `信件抠图-v3.png`，不得继续引用 v2 信纸素材。

#### `LetterContentOverlay`

独立的真实 DOM 交互层，叠加在 `LetterArtworkImage` 上方，负责顶部文字、正文输入和 Footer 的区域布局。

该层只约束交互内容区域，不代表信纸图片本身的尺寸。

#### `LetterTopArea`

组合日期、主题、问题和换题按钮。

v6 中按钮与日期、主题位于同一个 `MetaRow`，引导问题独占下一行。该区域内部元素关系紧密，应作为一个布局区域管理，不建议拆出 `DateLabel`、`ThemeLabel` 等无状态小组件。

#### `ShufflePromptButton`

有独立的点击、Hover、Active、Disabled 等状态，应作为按钮组件。

#### `LetterEditor`

负责正文输入、滚动和输入区域边界，应作为独立组件。

#### `SaveStatus`

复用 Figma 中的状态组件：

```text
default    # 空内容
saving
saved
error
```

`default` 状态不显示保存提示。

#### `LetterFooter`

负责底部左右两组内容的稳定对齐。

#### `CollectMemoryButton`

是独立页面操作入口，可作为轻量按钮组件。

### 4.2 不应单独拆为组件

以下元素作为父组件中的普通节点即可：

- 日期；
- 动态主题标签；
- 动态引导问题；
- 字数统计；
- 信件正文内边距；
- 信件正文复合底；
- 用户输入演示文字。

组件拆分依据是业务职责、状态和复用价值，不是 Figma Layer 数量。

## 5. 基准布局

### 5.1 页面舞台

精确基准：

```text
width: 1440px
height: 810px
aspect-ratio: 16 / 9
```

记录页必须与项目已实现的初始页共用同一套 `1440 × 810` 场景坐标体系。

```css
.record-page-stage {
  position: relative;
  width: 1440px;
  height: 810px;
  overflow: hidden;
}
```

窗口尺寸变化时，整个舞台统一等比缩放，不分别改变信纸内部元素的比例。

### 5.2 背景

```text
x: 0
y: 0
width: 1440px
height: 810px
```

要求：

- 使用 `没有信件的背景图`；
- 完整覆盖舞台；
- 不使用已删除的初始页背景；
- 不横向拉伸 1280 宽资源；
- 背景与页面采用相同的 16:9 比例。

### 5.3 信纸主体图片

v6 的 `信纸叠图` 使用 `信件抠图-v3.png`。它是完整舞台尺寸的透明图片资产：

```text
x: 0
y: 0
width: 1440px
height: 810px
```

它与记录页背景图完全对齐：

```css
.record-page-background,
.letter-artwork-image {
  position: absolute;
  inset: 0;
  width: 1440px;
  height: 810px;
}
```

素材校验值：

```text
PNG canvas: 1440 × 810px
non-transparent bbox: x 359–1099, y 176–678
non-transparent bbox size: 741 × 503px
```

透明内容边界包含信纸周围的阴影和叠放装饰，只用于核对资源及对齐，不得转换成 DOM 面板尺寸。信纸正面在 v3 中明显大于旧版，因此 DOM 内容层必须采用本版坐标，不得沿用 v5 的 `466px` 内容宽度。

规则：

- 不规定图片中“可见信纸区域”的独立宽高；
- 不把信纸可见区域实现成 `556 × 364px` 的 DOM 容器；
- 不裁切信纸叠图；
- 不对信纸叠图进行单独缩放；
- 背景图、信纸叠图和 DOM 交互层必须基于同一 `1440 × 810` 坐标系整体缩放；
- 正文输入的滚动和边界由 `LetterContentOverlay` 内的正文区域负责，不影响信纸图片尺寸。

### 5.4 信纸 DOM 内容区宽度

以下尺寸只约束叠加在图片上的真实 DOM 内容区，不代表信纸图片宽度。

根据新版参考图换算，正文容器与 Footer 的主要横向布局基准约为：

```text
x: 440px
width: 584px
right: 1024px
```

该宽度应作为以下区域的对齐基准：

- 正文容器；
- 底部状态和收藏区域；
- 顶部区的整体可用范围。

顶部文字使用略内收的视觉起点，约为 `x: 455px`；正文容器和 Footer 仍以 `x: 440px` 为布局边界。不要为了让所有文字墨迹边缘完全相同而对每个字形做绝对定位。

## 6. 各区域布局规则

### 6.1 信件顶部区

顶部区采用两层结构：

```text
MetaRow
└── 左：日期 + 动态主题标签
└── 右：换一个

PromptText
```

#### MetaRow 参考属性

```text
MetaRow:
  x: 约 455px
  y: 约 235px
  width: 约 567px
  height: 约 28px

日期与主题信息：
  line-height: 20px
  vertically centered in MetaRow

“换一个”按钮：
  x: 约 926px
  y: 约 235px
  width: 约 96px
  height: 28px
```

日期和主题处于同一基线，使用内容自适应宽度。二者应作为紧凑的 `MetaInfo` 组排列；不得沿用 v5 中日期 `38px`、主题 `73px`、间隔 `18px` 的示例固定宽度。`MetaInfo` 与右侧按钮使用 `space-between`，但 `MetaInfo` 内部不使用 `space-between`。

#### PromptText 参考属性

当前示例引导问题：

```text
x: 约 455px
y: 约 273px
available width: 约 567px
height: 38px
```

规则：

- 引导问题位于完整 MetaRow 下方，独占一行，不再与“换一个”按钮竞争横向空间；
- 换题按钮固定在 MetaRow 右侧，与日期/主题信息垂直居中；
- 顶部文字起点相对正文容器左边界内收约 `15px`；
- 按钮右边界与正文容器右边界保持约 `2px` 的视觉余量；
- 按钮文字不可换行；
- 当前问题池在该宽度下应尽量单行呈现；
- 如未来文案确需换行，最多两行且不得裁切；应由顶部区增高并联动调整正文可视高度，不能覆盖正文；
- 不使用省略号隐藏引导问题。

### 6.2 问题区与正文区的间隔

- v6 不显示独立的“问题与正文分隔线”；
- 当前单行问题文字底部与正文容器顶部之间约保留 `32px` 视觉间隔；
- 区域区分依靠留白和正文浅色复合底，不添加高对比度边框。

### 6.3 信件正文容器

新版正文容器参考属性：

```text
container:
  x: 约 440px
  y: 约 343px
  width: 约 584px
  height: 约 184px

padding:
  horizontal: 22px
  vertical: 18px

editor viewport:
  x: 约 462px
  y: 约 361px
  width: 约 540px
  height: 约 148px
```

正文容器规则：

- 正文从左上角开始；
- 使用固定内边距，文字与复合底边缘不贴靠；
- 容器尺寸在 `1440 × 810` 基准舞台中固定，随舞台整体等比缩放；
- `LetterEditor` 填满 editor viewport，长内容只在该区域内部纵向滚动；
- 正文不得延伸至 Footer；
- 正文容器的视觉底色与信纸纹理保持低对比；
- 不允许用户拖拽改变输入框尺寸；
- 隐藏浏览器默认 textarea 边框、背景和右下角 resize handle；
- 参考图中最后一行文字被裁切仅为排版示意，不是实现效果。正式页面不得通过 `overflow: hidden` 截断长正文；内容超出时必须出现区域内纵向滚动。用户主动滚动过程中，文字在视口边缘的自然裁切属于正常滚动表现。

### 6.4 信件底部操作区

底部使用两端对齐：

```text
左侧：RecordStatusGroup
右侧：CollectMemoryButton
```

布局参考值：

```text
x: 约 440px
y: 约 580px
width: 约 584px
min-height: 24px
```

规则：

- Footer 与正文容器使用相同的 `584px` 横向布局基准；
- 左侧状态组靠左，收藏按钮靠右，二者垂直居中；
- 保存状态与字数统计继续保持 `4px` 紧凑间隔，不使用 `space-between`；
- 保存状态和字数统计均使用内容自适应宽度，不再验收旧版固定的 `44px` 与 `46px`；
- 收藏按钮使用内容自适应宽度并与右边界对齐，不再使用旧版相对位置 `x: 371px`；
- 文案保持单行；
- 与左侧状态组不重叠；
- 文字视觉权重高于保存状态和字数统计。

### 6.5 正文区与 Footer 的间隔

- v6 不显示独立的“信件底部分隔线”；
- 正文容器底部到 Footer 顶部约保留 `53px` 留白；
- Footer 不得上移覆盖正文复合底，也不得下移超出信纸正面安全区域。

### 6.6 自动保存机制

保存状态包括：

```text
default
saving
saved
error
```

状态规则：

1. 页面初始进入时为 `default`；
2. `default` 状态的保存提示元素为空，不显示任何保存文案；
3. 用户输入时重新开始计时；
4. 用户连续停止输入 `1000ms` 后触发保存；
5. 开始保存时切换为 `saving`；
6. 后端保存成功后切换为 `saved`；
7. 后端保存失败后切换为 `error`；
8. 用户再次输入后，取消尚未触发的旧计时，并重新等待 1 秒。

MVP 阶段：

- 保存请求先使用 mock Promise；
- 默认可模拟成功并进入 `saved`；
- 应保留模拟失败的入口，以验证 `error` 状态；
- 后续替换真实后端调用时，不改变四态视觉规则。

Footer 显示规则：

- 字数统计始终可见；
- `default` 状态下不显示保存文案；
- `default` 状态下不应残留孤立的分隔点；
- `saving / saved / error` 状态下，保存状态与字数统计保持紧凑排列。

### 6.7 “换一个”主题与问题机制

点击“换一个”后，必须同时更新：

```text
动态主题标签
动态引导问题
```

切换规则：

1. 新主题框架不能与当前主题框架相同；
2. 从新的主题框架中随机选择一条引导问题；
3. 动态主题标签必须与引导问题所属框架一一匹配；
4. 不允许只换问题、不换主题标签；
5. 不允许主题标签与问题跨框架错配；
6. Figma 中的「宜 · 更像自己」是当前示例文案，正式页面使用下列动态主题文案。

框架匹配关系：

| 问题框架 | 匹配的动态主题标签 |
|---|---|
| 具体生活 | 注意让自己感觉好的瞬间 |
| 更像自己 | 发现更像自己的选择 |
| 对具体生活心存感激 | 感激具体的人、事和生活 |
| 不顺利的日子 | 积累关于自我力量的真实证据 |
| 真实生活过的痕迹 | 建立现在与未来自己的联系 |

### 7.3 文字层级

视觉层级从高到低：

1. 动态引导问题；
2. 收藏这份记忆按钮；
3. 正文；
4. 日期与主题标签；
5. 保存状态与字数统计。

标题使用衬线字体形成信件感；功能性文字使用无衬线字体保证识别度。

### 7.4 信纸图片和正文区域

- 信纸主体必须直接使用 `1440 × 810` 的 `信件抠图-v3.png` 图片资产；
- 正文复合底覆盖约 `584 × 184px`，比信纸主体略有区分，但保持轻、低对比；
- 正文区域使用柔和圆角，参考圆角约 `10–12px`；
- 正文复合底不得遮掉信纸纹理，建议使用低透明度暖白叠层，不使用不透明纯白；
- 不使用明显灰色输入框样式；
- 不将文字、按钮烘焙到信纸图片中。

### 7.5 按钮样式

“换一个”：

- 胶囊形描边按钮；
- 低对比棕色描边；
- 包含刷新图标；
- 背景保持轻量；
- 不应成为页面主按钮；
- 按钮约为 `96 × 28px`，圆角取高度的一半；
- 文字与刷新图标作为一个居中的紧凑内容组，图标不贴右边界。

“收藏这份记忆 →”：

- 文本型操作；
- 不使用大面积实心底色；
- 通过字重、颜色和箭头建立主要操作感。

### 7.6 区域分隔方式

- v6 不渲染问题分隔线和底部分隔线；
- 顶部、正文和 Footer 通过纵向留白建立节奏；
- 正文浅色复合底是页面中唯一明显的区域容器，不额外增加卡片描边或投影；
- 信纸素材自身的边缘、纹理和阴影保持原样，不用 CSS 重复绘制。
